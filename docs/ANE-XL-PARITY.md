# ANE-XL: reproducible compiled-bucket parity probe

The real FluidInference fp16 L128 compiled model passes this three-case smoke
check against local laya-mlx float16 on an Apple M1 Max. This is evidence for
continuing evaluation, **not approval to route production traffic**. No ANE-XL
backend, router wiring, service restart, or paid API call is part of this artifact.

## Recorded result

[Machine-readable evidence](evidence/anexl-l128-cpu-ne.json), run 2026-09-22 UTC:

| Fixture | Question type | Max option probability difference | Max action probability difference | Both argmaxes agree |
|---|---|---:|---:|---|
| `choice_refund` | choice | 0.004218705 | 0 | yes |
| `score_outage` | score | 0.001323218 | 0 | yes |
| `noul_delivery` | noul | 0.000189876 | 0 | yes |

These differences are identical for bucket-padded and natural-length MLX in this
run. Each fixture passes a provisional absolute-probability tolerance of 0.02
for options and actions, plus agreement of both argmaxes. CLI tolerances are
configurable; they are smoke-test thresholds, not a calibrated production gate.

The JSON contains timestamped model load events, the actual compiled MIL
signature, artifact hashes, package versions, original requests, normalized
questions, complete rendered token IDs/tokens/decoded text, marker positions,
calibration, probability distributions and per-case diffs. It is regenerated by
the script, not hand-edited. Prompt data is recorded verbatim: use synthetic or
approved inputs before publishing a report.

## What the probe checks

`tools/probe_anexl_parity.py` loads the real `.mlmodelc` bundle with
`coremltools.models.CompiledMLModel`; no re-export or PyTorch is involved.
It independently uses FluidInference's tokenizer with laya-mlx's canonical
renderer, then requires exact token-ID and marker-position equality with
`Agent.prepare` using the MLX tokenizer. The renderer uses source
`max_len=1024` and `head_max_len=256`:

```text
[CLS] <type> question: <instructions> [SEP]
[MASK] <option 0> [MASK] <option 1> ... [SEP] <state> [SEP]
```

The tokenizer spells CLS/SEP/MASK as `<bos>`/`<eos>`/`<mask>` in the stored prompt.
Canonical option/instruction budgets still apply; the probe rejects state
truncation at the source maximum and rejects bucket overflow instead of clipping.

Inputs are padded only after rendering: int32 `input_ids` and `attention_mask`
`[1,L]`, float32 `marker_map` `[1,32,L]` with one marker per used option, and
float32 one-hot `question_type` `[1,3]`. Unused marker slots are zero.
The actual MIL program and returned arrays must match the expected names,
dtypes, shapes and finite probability distributions.

Only used option logits participate in the calibrated softmax. Temperature
selection mirrors the source config (`temperature_by_options` first, otherwise
per-question temperature). CoreML's embedded action probabilities are compared
with softmax of MLX action logits. MLX runs once with exactly the bucket padding
and once at its natural length to expose padding-sensitive behavior.

Exit status is 0 for a complete pass, 2 for a completed numerical parity failure,
and nonzero for invalid inputs/load/runtime errors. Results persist after each
completed fixture; require both `complete: true` and `passed: true`, as well as
exit status 0. An interrupted or failed run must not be mistaken for a pass from
a previously existing output file.

## Reproduce

Requires macOS on Apple Silicon. This run used Python 3.13.12, CoreMLTools 9.0,
MLX 0.32.2, NumPy 2.5.3 and tokenizers 0.23.2. Use an isolated environment:

```sh
uv venv /tmp/jevalaya-anexl-parity-venv --python 3.13
uv pip install --python /tmp/jevalaya-anexl-parity-venv/bin/python \
  coremltools==9.0 mlx==0.32.2 numpy==2.5.3 \
  tokenizers==0.23.2 huggingface-hub==1.32.0
```

Use a local laya-mlx checkout at commit
`fc1df62828a3fedf4d8229fdac1cbd85f1cdf337`; the report also hashes the actual
`agent.py` and `common.py` used. Model download is a separate, explicit step:

```sh
hf download FluidInference/laya-coreml \
  --revision 7b8d7a2b7e28e746c6ecaad44bbcd5cf251a4fcc \
  --include 'laya_multilingual_fp16_L128_options32.mlmodelc/*' \
  --include tokenizer.json --include config.json

hf download aac6fef/laya-multilingual-mlx \
  --revision f2b4faf51023039425946074e2cf1361d2db11d5

hf download convaiinnovations/laya multilingual/rl_agent_config.json \
  --revision 1c5edc17a7acd8701df6fc341c0d179f1c62c982
```

Pass the local snapshot directories printed by `hf download`. From the jevalaya
repo, substituting your own paths:

```sh
PYTHONDONTWRITEBYTECODE=1 /tmp/jevalaya-anexl-parity-venv/bin/python \
  tools/probe_anexl_parity.py \
  --coreml-dir /path/to/FluidInference-snapshot \
  --mlx-model-dir /path/to/aac6fef-snapshot \
  --source-config /path/to/convaiinnovations-snapshot/multilingual/rl_agent_config.json \
  --laya-mlx-path /path/to/laya-mlx \
  --bucket 128 --compute-units cpu_ne --mlx-dtype float16 \
  --output /tmp/anexl-parity-new-run.json

PYTHONDONTWRITEBYTECODE=1 /tmp/jevalaya-anexl-parity-venv/bin/python \
  -m unittest discover -s tools -p 'test_probe_anexl_parity.py' -v
```

The probe itself is offline and does not download missing files. Nine pure helper
tests cover padding, marker orientation, all question types, exact bucket lengths,
32 options, overflow rejection, invalid outputs and calibrated comparisons.
These tensor-construction tests do not imply real inference at every boundary.

For more evidence, download the corresponding compiled bucket and use
`--bucket 256`, `512`, or `1024`. `--cases cases.json` accepts a nonempty JSON list
of `{id, state, question}` objects; `question` is the same single-question object
used by `/predict`. The built-in fixtures are visible at the top of the script.

## Limits and next admission checks

- Only L128 and three short English-language prompts on the **multilingual**
  checkpoint were run. No evidence yet for longer buckets, multilingual text,
  maximum options, near-ties, or maximum-length real inference.
- All action distributions were saturated at `[1, 0]`. Their zero difference does
  not establish agreement on uncertain/escalating cases or confidence thresholds.
- `CPU_AND_NE` specifies allowed compute units; it does not prove exclusive ANE
  execution. The recorded loads/predictions are diagnostics, not latency benchmarks.
- CoreML declares source `convaiinnovations/laya`, `multilingual/`, revision
  `1c5edc17a7acd8701df6fc341c0d179f1c62c982`. MLX declares a different source repo,
  `convaiinnovations/laya-multilingual`, revision
  `052592a15d198d9ad47da779604259b10b47b7aa`. Configs match and observed outputs
  agree closely, but this does **not** prove identical source weights.
- The Python renderer is the reference here. This does not establish parity of
  any future Rust ANE-XL adapter, tokenizer selection, lifecycle or fallback path.

Before production admission: resolve source-weight provenance, evaluate every
bucket on a broader fixed fixture set (especially near-ties and uncertain
actions), then test the actual Rust adapter against these same recorded prompts.
